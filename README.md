# 本地临床病历文本抽取与归一化管线

一个**纯本地、确定性、可并发、可解释**的病历 NLP 管线。用本地构造的病历文本与
术语资源模拟真实输入，完成：

1. 自由文本**分节与句子切分**，正文归一为带原文字节位置的结构化片段；
2. **概念抽取**与**否定 / 不确定性**判定，修饰词作用范围明确；
3. **缩写上下文消歧**与**术语资源版本兼容**（升级 / 回退可复现历史结论）；
4. 重复处理、术语版本切换、并发处理下结论**完全一致**，无新旧规则混合。

> 约束：仅使用 Go 标准库；不访问外部服务、不下载模型、不使用任何真实病历数据。
> 所有语料与术语均为仓库内置的本地构造资源。

## 目录结构

| 包 | 职责 |
| --- | --- |
| `pkg/segment` | 分节、句子切分、原文位置记录、畸形文本检测 |
| `pkg/terminology` | 版本化术语注册中心：概念、触发词、修饰词、缩写规则（内置 v1 / v2） |
| `pkg/extract` | 概念命中、否定 / 不确定作用域、缩写消歧、确定性优先级仲裁 |
| `pkg/pipeline` | 版本快照绑定、稳定指纹、并发安全编排、可读报告 |
| `cmd/note-demo` | 本地演示入口 |

## 快速开始

```bash
# 构建
go build ./...

# 运行全部测试（含畸形文本、版本切换、并发场景）
go test ./... -v

# 带竞态检测
go test -race ./...

# 本地演示（默认最新版本 v2）
go run ./cmd/note-demo
go run ./cmd/note-demo -version v1
```

单测在 `-v` 模式下会逐条打印**原文片段、命中规则与判定依据**，例如：

```
原句=无胸痛；有咳嗽。 片段="胸痛"[16:22] 方式=TRIGGER 极性=NEGATIVE
    规则/依据: 子句紧凑起点=0
    规则/依据: 作用域内否定词=无，间隔rune=0
    规则/依据: 结论=NEGATIVE/确定（否定词覆盖）
```

## 一、分节与切分规则

实现见 `pkg/segment`。

### 1. 分节

- **仅整行匹配标题白名单**才视为小节标题。匹配前对整行做归一：去首尾空白、
  去结尾中英文冒号（`:` / `：`）、ASCII 大写（中文不变）。
  白名单含 `主诉/现病史/既往史/个人史/查体/辅助检查/诊断/处理` 及对应英文
  （`CHIEF COMPLAINT`、`HISTORY OF PRESENT ILLNESS` 等）。
- **缺标题内容不丢弃**：第一个标题之前出现的正文归入一个匿名小节
  （`Header == ""`），并在该小节标记 `NO_HEADER`，给出位置与原因。
- **重复标题分别保留**：同一标题每出现一次都生成独立 `Section`，从第二次起在
  该小节标记 `DUPLICATE_HEADER`，两段正文不会被合并或静默覆盖。

### 2. 句子切分

- 句子结束符为 `。！？.!?`；**换行不是句子边界**。
- **跨行内容合并**：同一小节内的连续行合并为同一句，连续空白（含换行、制表符）
  折叠为单个空格。
- 每个 `Sentence` 带 `Start/End` 字节偏移，可精确回溯原文
  （`raw[s.Start:s.End]`），多字节 UTF-8 安全。

### 3. 畸形文本：可区分的处理 / 拒绝原因

所有异常都带 `Kind`、字节位置与说明，绝不静默丢弃：

| Issue 类型 | 触发条件 | 处理方式 |
| --- | --- | --- |
| `EMPTY_TEXT` | 空串或纯空白 | 拒绝切分，仅返回该问题 |
| `BINARY_CONTROL_CHAR` | 含 NUL 等控制字符 | 判定为二进制 / 损坏输入，**整体拒绝**，不产出任何小节 |
| `NO_HEADER` | 正文先于任何小节标题 | 保留到匿名小节并标记 |
| `DUPLICATE_HEADER` | 标题重复出现 | 每次出现独立成节并标记 |
| `TRUNCATED_LINE` | 末个非空行无尾换行且无句子结束符、又不是标题 | 内容保留，同时标记疑似截断 |

### 4. 确定性

`Split` 是纯函数：无随机、无 map 遍历依赖、无时间/全局状态。同一文本重复切分的
小节、句子、偏移、问题列表逐字节一致（见 `TestDeterministicRepeatedSplit`）。

## 二、否定与不确定性判定语义

实现见 `pkg/extract`。

### 1. 匹配方式

- 句子先转成“**去空白 + 大写**”的紧凑串并保留到原文的字节偏移映射，
  因此跨行、多空格都能命中且位置准确。
- **触发词**：大小写不敏感的子串匹配（长词优先，避免 `COVID 19` 被 `COVID` 截断）。
- **缩写**：按独立 ASCII token 边界匹配（`DM`、`HTN`、`COVID-19` 等），
  不会误命中在词内。

### 2. 修饰词作用范围（关键）

- 修饰词**只向后作用**，且限定在**同一子句**内。子句边界为
  `，,、；;。！？.!?`。
  - `无胸痛；有咳嗽。` → 胸痛 **NEGATIVE**，咳嗽 **POSITIVE**（否定不跨分号）；
  - `发热、咳嗽，无胸痛。` → “无”只否定胸痛，不越过顿号 / 逗号波及发热、咳嗽；
  - `否认发热。咳嗽明显。` → 否定不跨句。
- 修饰词与概念之间的距离按**非空白 rune 数**计，超过版本配置的
  `ForwardWindow`（内置为 24）即失效，防止一个否定跨越冗长表述波及远处肯定句。
- 内置否定词：`否认/未见/无/排除/未及/NO/NOT/WITHOUT/ABSENT/NEGATIVE FOR/DENIES/...`；
  不确定词：`可能/待排/疑似/不除外/考虑/POSSIBLE/SUSPECTED/QUESTIONABLE/LIKELY/...`。

### 3. 极性与确定性优先级

- 极性取值：`POSITIVE` / `NEGATIVE` / `UNCERTAIN` / `AMBIGUOUS`。
- 确定性级别：`确定(肯定或否定) > 不确定 > 歧义待定`。
- 同一子句内否定与不确定并存时，取**离命中更近**者；等距时**否定优先**
  （`可能无发热` → NEGATIVE）。
- **同一句同一概念多次出现**按确定性优先级仲裁，而非任取其一：
  `疑似发热，但最终无发热。` → 最终 **NEGATIVE / 确定**（确定否定压过不确定）。
- 跨句子 / 跨小节再按概念 ID 归并为 `Finding`，最终极性同样按确定性优先级选择，
  **每次命中（`Mention`）都保留**并附完整依据，可追溯到具体句子与规则。

## 三、缩写消歧与术语版本

### 1. 上下文消歧优先级

- 每条缩写规则带若干**上下文线索词**和优先级 `Priority`。
- 对某缩写的所有候选概念，统计其线索词在**当前句子**中的命中数：
  - **唯一最高分** → 解析为该概念（如神经科语境的 `MS` → 多发性硬化，
    心超 / 瓣膜语境的 `MS` → 二尖瓣狭窄）；
  - **最高分并列**或**完全无线索** → 不显式猜测，输出占位概念
    `AMBIGUOUS:<缩写>`，极性 `AMBIGUOUS`（待定），并在依据中说明原因。
- 候选同分按概念 ID 字典序打破排序，但**不会**据此强行选定概念——只用于保证
  处理顺序确定。

### 2. 版本化术语资源

注册中心 `terminology.Registry` 内置两个不可变版本（见 `pkg/terminology/registry.go`）：

- **v1**：缩写 `DM→糖尿病`、`HTN→高血压`、`CHD→冠心病`、`TB→结核` 均有效；
  `MS` 有两个义项（多发性硬化 / 二尖瓣狭窄）；新冠只有长触发词，**未收录** `COVID` 缩写。
- **v2（最新）**：**下线** `DM/CHD/TB` 缩写（长触发词如“糖尿病/结核/冠心病”
  仍然有效）；**新增** `COVID→新冠`；`MS` **新增第三义项**代谢综合征。
- 概念 ID（如 `DIABETES`、`MULTIPLE_SCLEROSIS`）跨版本稳定，便于长期追踪。

### 3. 为什么升级 / 回退不会改变历史结论、也不会新旧混合

- 每个 `Version` 是**不可变快照**；`Process` 开始时通过
  `Registry.Snapshot(version)` 取一次快照，整份文本的切分与抽取都只引用该快照。
- 即使处理期间其他 goroutine 切换了“最新版本”，已取得的快照也不受影响——
  **一份文本整体基于某一个确定版本**，不会前半句按 v1、后半句按 v2。
- 用 `pipeline.WithVersion(ctx, "v1")` 即可按历史版本**原样复现**当时结论；
  未知版本返回显式错误（`未知术语版本`），绝不静默回落到默认版本。
- 每个 `Finding` / `Output` 都标注实际使用的版本名，文本还带 SHA256 指纹。

并发安全由注册中心的 `sync.RWMutex` 与不可变快照保证；`Process` 本身无共享可变
状态，可被多 goroutine 并发调用（`go test -race` 验证）。

## 四、使用方式

```go
reg := terminology.NewRegistry()
p := pipeline.New(reg)

ctx := pipeline.WithVersion(context.Background(), terminology.V2) // 或 V1
out, err := p.Process(ctx, noteText)
if err != nil { /* 例如未知版本 */ }

fmt.Print(out.String())          // 确定性可读报告（含原文片段、规则、依据）
f := out.FindingsByID()          // 概念 ID -> Finding
ids := out.SortedFindingIDs()    // 字典序稳定的命中列表
```

`Finding.Polarity` 为最终结论，`Finding.Mentions` 保留每一处命中及其证据链
（所在小节、原句、字节区间、命中方式、作用域内修饰词、判定理由）。

## 五、设计取舍说明

- 规则 / 词典方法而非模型：保证离线、零依赖、可审计、结论可复现。
- 中文与英文统一用“大写 + 去空白”归一；偏移始终相对原始字节串计算，
  避免归一化后定位错位。
- 任何“无法确定”的情况（二进制输入、未知版本、缩写歧义、疑似截断）都**显式标记
  或拒绝**，而不是猜测或静默吞掉，从而满足“结论确定且失败原因可区分”。
